## 実施結果（2026-08-01・Evidence Level 4）

### 実装

**`scripts/check_residual.py`**: `_PARENT_ABSENT_CODES` と `_parent_absent()` を追加し、
`guarded` が親不在の例外で `[]`（残留ゼロ）を返すようにした。

判定は**実際に観測したエラーコードだけ**（`resourcegroupnotfound` / `parentresourcenotfound`）。
`"not found"` のような広い文言を入れると**資格情報エラーまで「残留ゼロ」に化けて
撤収の失敗を見逃す**ため、意図的に狭くしている。この方針自体もテストで固定
（判定文字列が `notfound` 終端であること）。

**`tests/core/test_predictor.py`**: 3基盤のマウント形をパラメタライズ。

| 基盤 | 環境変数 | 配置 |
|---|---|---|
| SageMaker | `MODEL_DIR` | 直下（基盤が `model.tar.gz` を展開） |
| Vertex | `MODEL_DIR` | 直下（シムが GCS から取得） |
| Azure ML | `AZUREML_MODEL_DIR` | **1段深い**（出力フォルダ名を保つ） |

「どのレイアウトでも同じ予測値」も検証対象。Tier B はこの推論コンテナを使わないため対象外。

### 実クラウド検証（完全撤収後）

`mcml-dev-rg` を削除しきった状態で実行:

```
-- FAIL/ERROR 0 件 / 全 2 件
```

修正前は同じ状況で `azureml/online_endpoint` と `azureml/registered_model` が
**ERROR 2件**（`ResourceGroupNotFound` / `ParentResourceNotFound`）になり、
「調べられなかった」と「残留ゼロ」が区別できなかった。現在は azureml の行自体が出ず、
残る2件は Snowflake の既知 WARN（stage 成果物 / Fail-safe）。

### 副産物: 残留の再現性が確定した

2回目の構築でも destroy が **9/10 で失敗**し、`Application Insights Smart Detection` が
RG に残った（1回目と同一）。**偶発ではなく Azure の構造的な性質**であることが確定した
（`docs/comparison/residual-resources.md`）。
