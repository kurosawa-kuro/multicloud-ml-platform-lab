# 修正03: 設定の二重化を解消する（use_spot / wheel 名）

Weight Class: Standard（`infra/**` を触るため owner 確認境界に接触。apply はしない）
親調査: [2026-08-01-5基盤完走後の再設計と修正順序.md](./2026-08-01-5基盤完走後の再設計と修正順序.md) §2.1 §2.4 / G2 / 順序#3

## Goal

同じ意味の値が2箇所にある構造を無くす:

1. `common.use_spot` — Vertex/SageMaker は adapter、Azure は TF 変数（`vm_priority`）と
   2系統に割れている。全 Config dataclass に `use_spot` を持たせ、
   **効かない基盤（Databricks/Snowflake）では明示的に `ConfigError`** で落とす
2. Databricks の wheel 名 — `env/config.yaml:76` と
   `infra/modules/databricks/main.tf:36` にバージョン込みで重複。pyproject から導出する

## Value

failure detection / integrity。`_resolve()` が dataclass に無いキーを黙って捨てるため、
「設定したのに効いていない」が検出不能。Azure の LowPriority 問題で実際に切り分けコストを払った。

## Context

`platforms/config.py:200` の `allowed = {f.name for f in fields(...)}` が黙殺の実体。
wheel 名は config.yaml:75 のコメント自身が「ずれると entry point を引けない」と警告済み。

## Scope

- 5つの Config dataclass への `use_spot` 追加（効かない基盤は `__post_init__` で拒否）
- Azure: `TF_VAR_compute_cluster_vm_priority` を config 由来にする配線（変数の値渡しのみ）
- wheel 名: pyproject の `project.name` + `version` から組み立てる関数を1つ作り、
  config.yaml のハードコードを削除。TF 側は変数経由で同じ値を受ける
- `_resolve()` に「common キーが捨てられたら警告ログ」を追加

## Non-scope

- terraform apply の実行（コード変更と plan 確認まで）
- Spot の実挙動検証（H-5 = SageMaker Spot 実測は修正07以降の実クラウド検証で）

## Plan

2. 実装 → `make test`
3. `terraform plan`（azure-dev / dbx-dev）で差分ゼロ（値が同じなら no changes）を確認

- [ ] `make test` green
