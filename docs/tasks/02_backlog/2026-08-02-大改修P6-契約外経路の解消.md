# 大改修 P6: 契約外経路の解消 — pipeline・config・handoff

Weight Class: Standard / 親調査: [大改修 調査と方針 第2版](../01_idea/2026-08-02-大改修-5インフラ制約起点の再設計-調査と方針.md) §5-P6
P2/P3 の後に実施（adapter の公開面が P2 で動くため）。

## Goal

adapter 契約（PlatformAdapter Protocol）の外側で動いている経路を、契約の内側 or 明示的な基盤別公開面へ移す。

## Value

integrity / dev speed。

## Context

パイプラインは3基盤で形が違う=非対称が正の領域（番人 pin 済み）。だから Protocol を太らせるのではなく、**具象型を明示的に使う**方向で解消する（all-or-none 規則との整合）。

## Scope

1. `run_pipeline.py`: 具象 adapter 型を明示的に受け取る形へ。`adapter._config.*` 直叩きは基盤別の公開プロパティ（`service_account` / `execution_role_arn` 等）で解消。`adapter.sdk` / `.sagemaker` / `.client` の直叩きも同様。`_null_sink()` は `tests/fakes/telemetry.py` 相当へ寄せ、sink 契約一覧の検出対象に入れる。`__import__` の除去
2. `config.py`: platform 節の未知キーを common 節と同じ ConfigError へ（無言 drop の廃止）+ `test_platforms_config` に config.yaml 側の検査を追加
3. handoff キーの一本化: `factory.deploy_reference` と `resume.MODEL_REFERENCE_KEYS` を単一対応表に統合し、SageMaker の「書くキー ≠ deploy が使うもの」非対称を1箇所で明示
4. config dataclass を adapter ファイルから分離するかの再評価（P2/P3 後の構造で all-or-none 番人と突き合わせて判断。やらない結論も可 — 結論を task に記録）

## Non-scope

- PlatformAdapter Protocol へのメソッド追加（非対称な操作を契約で均さない）
- パイプライン対応基盤の拡大

## Done

`run_pipeline.py` に private 属性アクセス・生 SDK ハンドル直叩きゼロ（検査可能な形で）。config.yaml の未知キーが platform 節でも即エラー。handoff キーの定義が1箇所。`make test` 緑。

## Evidence

Level 2: 未知キー検査の赤の実演（仮キーを config.yaml に足して ConfigError）+ private アクセス検査（番人化する場合はその赤の実演）+ `make test` 緑。パイプライン build 経路は実 outputs でのオフライン組み立て確認（クラウド不要・修正11 と同手順）。

## Stop / Ask Owner If

- 公開プロパティの切り方が「基盤別に生やす」以外（共通 Protocol 拡張）に倒れそうになったら停止 — inside-out のサイン
- 4 の分離判断で config 解決の挙動が変わる案しか無ければ確認
