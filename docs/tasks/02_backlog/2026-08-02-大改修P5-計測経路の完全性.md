# 大改修 P5: 計測経路の完全性 — collect / residual / Makefile / schema

Weight Class: Standard / 親調査: [大改修 調査と方針 第2版](../01_idea/2026-08-02-大改修-5インフラ制約起点の再設計-調査と方針.md) §4-B・§5-P5
P4 と並行可。

## Goal

計測データの収集・残留検査・実行経路の「黙って欠測する」構造を潰す。主成果物（比較レポート）の一次データを守る改修。

## Value

collection accuracy / failure detection。

## Context

第2回調査の新発見群: `make tf-destroy` の `--record` 抜けは P0 で先行修理済み想定。残りは収集系の未配線・矛盾・死んだ経路と、検査の網羅性。

## Scope

1. `collect_costs`: Snowflake の `Session.builder.getOrCreate()` を check_residual と同じ明示接続へ（実測で禁じられた方法の除去）。Vertex / Azure は配線するか「未配線」を CLI から明示的に外す — **黙って空を返す現状の廃止**
2. `collect_jsonl --platform` の死んだ引数（必ず exit 2）を削除 or 実装
3. `check_residual` の kind 網羅リストを宣言し、リスト連結への追加漏れを pin（docstring が自認する「3回目の再発」の構造的防止）
4. `sql/schema.sql` の値域 ↔ `schemas.py` Enum の pin（CHECK 制約 or 生成テスト。`test_sql_contracts` は現状文字列検査のみ）
5. Makefile: `tf-init` を `tf_backend.py` 経由に統一（現状全5環境で動かない）/ `PLATFORM ?= vertex` で死んでいるガード節と `distribute --all` 経路の修理 / `.PHONY` 補完 / CLAUDE.md のコマンド節と Makefile の一致
6. `neon-dev` 環境の扱いの宣言（意図的な非 IaC 管理なら module 削除 + コメント / 管理するなら実装）— owner 判断で分岐

## Non-scope

- cost_snapshots のスキーマ変更・新しい収集経路の追加
- 残留検査の新 kind 追加（網羅リストの仕組みだけ作る）

## Done

「黙って欠測・黙って無効」の経路がゼロ（欠測は必ず理由付きで出力に現れる）。`make test` 緑 + 該当スクリプトの単体実行で判定。

## Evidence

Level 2: 各修正の before/after のコマンド出力（例: `collect_costs --all` で Vertex/Azure が「未配線」を明示して出る / kind を1つ連結から外すと pin が赤）。tf-init は実クラウドなしで検証できる範囲（backend-config フラグ生成まで）+ 実 init は次回クラウド作業時に確認。

## Stop / Ask Owner If

- `neon-dev` の扱い（6）は owner 判断そのもの — 着手前に確認
- `collect_costs` の Vertex/Azure を「配線する」に倒す場合、SDK 追加依存が要るなら確認
