# 大改修 P1: 正本と番人の修理

Weight Class: Standard / 親調査: [大改修 調査と方針 第2版](../01_idea/2026-08-02-大改修-5インフラ制約起点の再設計-調査と方針.md) §4-A・§5-P1
**P2 以降（層を動かす改修）の前提。計器が壊れたまま改修しない。**

## Goal

大改修の土台となる正本ドキュメント（02_architecture）と番人テストの劣化を直し、「647 緑 = 規則遵守」と言える状態に近づける。

## Value

failure detection / docs canonicalization。

## Context

第2回監査の発見（親調査 §4-A）: 手順3表が実装と矛盾（A1）、同一SHA担保の中核 assert が空振り（A2）、AST 分岐検査に `databricks` 欠落ほか3穴（A3）、相対 import 素通り（A4）、未文書規則14件（A6）等。

## Scope

1. **02_architecture 手順3表の更新**: Vertex パイプライン行を「P3 撤回・orchestrator 新設」の現実へ / 「5基盤レイアウト parametrize」→「Tier A 3基盤」
2. 番人修理（各件、**修理前に赤の実演**を Verification に記録）:
   - `test_no_platform_branching_in_ml`: 語彙に `databricks` 追加・`ast.If` 以外の分岐形式・対象範囲の判断
   - `test_code_revision_parity`: 空振りの可視化（PRE_RESET 5件のみなら理由付き明示 skip）
   - import 検査の相対 import 素通り穴（`node.level`・前方一致）を塞ぐ — **P2/P3 の前に必須**
   - adapter 横断 import 検査の二重実装を1本化
3. 未文書規則の昇格（14件、親調査 §4-A6 の一覧）: 死蔵の禁止 / Tier B tfstate 規則 / SystemExit 契約 / teardown 冪等 等 → 02_architecture・該当 specs へ
4. `make lint` への mypy 追加（または別ターゲット）+ pytest markers の定義

## Non-scope

- 中核 assert（tree 一致）の復活 — 5基盤 run 再取得（P2+P3 後の一括 EL4）まで不可能
- 層の移動・コード構造の変更（→ P2/P3）

## Done

上記4項が入り、`make test` 緑（意図的に skip 化した項目は理由が出力に現れる）。02_architecture の手順3表が実装・番人と一致。

## Evidence

Level 2: 各番人修理について「修理前の穴の赤の実演」（例: core/ml に databricks 分岐を仮置きして旧検査が緑のまま・新検査で赤）のコマンド出力を task に記録。mypy は初回実行の結果（既存違反があれば件数と扱いの判断）を記録。

## Stop / Ask Owner If

- mypy 初回実行で既存違反が大量（>30件目安）に出たら、修正方針（一括 / 段階 / 除外設定）を owner に確認
- 未文書規則の昇格先で 02_architecture の構成変更が必要になったら、変更案を出して確認
