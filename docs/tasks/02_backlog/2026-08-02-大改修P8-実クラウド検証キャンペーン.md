# 大改修 P8: 実クラウド検証キャンペーン（一括 EL4）+ 最終修正

Weight Class: **Heavy**（Task Contract Full）/ 親調査: [大改修 調査と方針 第2版](../01_idea/2026-08-02-大改修-5インフラ制約起点の再設計-調査と方針.md)
検証戦略は **owner 採用済み**（2026-08-02 [decision-log](../../decisions/decision-log.md)）:
**「P0〜P7 をローカル証拠で完了 → 検証キャンペーン1回 → 最終修正」**。実施時に Owner Approval（日程・予算）。

## Goal

大改修（P0〜P7）の全変更を、5基盤 × Golden Path 1周の一括実クラウド検証で実証し（EL4）、検出欠陥の最終修正まで含めて大改修を閉じる。あわせて5基盤の新 run を記録し、`PRE_HISTORY_RESET_REVISIONS` の免除リストを削除して parity 中核 assert を復活させる。

## Value

integrity（大改修全体の実証）/ failure detection（ユニット緑のまま実クラウドで出る欠陥の検出 — 前回実績6件）。

## Scope

1. **チェックリストの事前作成（実施前・必須）**: 「何が観測されたら FAIL か」を先に決める（evidence-policy）。最低限含む項目:
   - 5基盤 × Golden Path（apply → 学習 → Neon 到達 → 登録 → 1件推論 → destroy → 残留記録）
   - P2: 記録の意味論不変（write_path / attempt / failure_class が CLI・パイプライン両経路で従来どおり）
   - P2-O2（D1 で採用の場合）: Snowflake 失敗 JSONL が stage に証跡として残ること（意図的な失敗を1回起こす）
   - P3: 移設後の配布物（学習イメージ・wheel・zip・orchestrator）が5基盤で起動すること
   - D5: `serving_image_uri` 未設定が即エラーになること
   - P5: `make tf-destroy` 経由で残留が infra_events に記録されること / `tf-init` が実 backend で通ること
   - RMSE / 1件推論の予測値が既録値と一致（破綻条件の再確認）
2. **事前の生存確認**: Snowflake トライアル期限・Databricks PAT・Azure クレジット（失効 **2026-08-30**）
3. キャンペーン実施（5基盤・destroy まで）
4. **最終修正ラウンド**: 検出欠陥を修正 → 必要なら該当基盤のみ再検証（1ラウンドで閉じない前提を許容）
5. 免除リスト削除: 新 run 記録後に `PRE_HISTORY_RESET_REVISIONS` を削除し、`test_code_revision_parity` の tree 一致 assert を本来の強さへ戻す（既存の撤退条件の履行）
6. 結果の記録: 比較レポートへの**追記**（過去実測値は書き換えず並べる規約）・decision-log の `結果` 行更新・P2/P3 の `04_verifying/` → `05_done/` mv

## Non-scope

- 新機能・新比較軸の追加
- 過去実測値・既存レポート記述の書き換え（追記のみ）
- キャンペーン前の個別クラウド検証（単独でクラウドを起こさない）

## Risk

- 検証の一点集中: P2 の設計を覆す反例が出た場合、手戻りが P2〜P7 に波及。緩和 = コミット粒度 P 単位（bisect 可能）・撤退条件（下記）
- 期限: Azure 2026-08-30。Snowflake トライアル状態は着手前まで不明
- 新 run は `baseline_runs` view の境界（2026-08-01 15:00 UTC）以後なので**比較母集団には混ざらない**（確認済み）

## Change Condition

P0〜P7 の完了（P2/P3 は `04_verifying/` 到達 = ローカル証拠で実装・基本検証済み。P7 は挙動不変のため未完でも実施可だが、原則は順序どおり）+ チェックリストの owner レビュー + 日程・予算の Owner Approval。

## Done Condition

チェックリスト全項目が緑（FAIL 項目は修正 → 再検証で緑）+ 5基盤の新 run が Neon に記録され RMSE / 予測値が既録値と一致 + 免除リスト削除後の `make test` 緑 + 比較レポート追記完了。

## Owner-only Decisions

- 実施日程（Azure 8/30 期限との兼ね合い）と予算枠
- Snowflake トライアル失効時の扱い（再トライアル / 4基盤で実施）
- 最終修正が2ラウンドで閉じない場合の続行判断

## Capability Boundary

実クラウド5基盤の構築・実行・削除 + Neon への実書き込み。予算は月額枠内（超えそうなら事前相談）。

## Allowed Paths

全リポジトリ（最終修正のため）。ただし修正は「検出欠陥の修正」に限定し、新規機能・追加リファクタは follow-up task へ。

## Forbidden Paths

`docs/comparison/` の既存実測値・既存記述の書き換え（追記は可）/ `docs/decisions/` の過去エントリ書き換え（`結果` 行の追記は可）。

## Rollback Trigger

- P2 の設計自体を覆す反例 → 最終修正で粘らず該当 P を rollback し、個別検証方式へ切り替え（decision-log の撤退条件）
- 月額予算の超過見込み → 停止して owner へ
- 2026-08-30 までに Azure 分を実施できない → 4基盤で先行し Azure は「条件付き」判断へ

## Evidence Required

Level 4: 各チェックリスト項目に実測の出力（コマンド出力・Neon の SELECT 結果・PipelineJob/学習ジョブの終了状態）を紐付けて記録。「緑のワークフロー」だけを証拠にしない。
