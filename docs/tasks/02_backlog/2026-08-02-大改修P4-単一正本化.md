# 大改修 P4: 単一正本化 — 依存 pin・serving 契約・outputs 契約・名前

Weight Class: Standard / 親調査: [大改修 調査と方針 第2版](../01_idea/2026-08-02-大改修-5インフラ制約起点の再設計-調査と方針.md) §5-P4
P5 と並行可。P2/P3 と独立に着手可能（衝突しそうな箇所は adapter 定数まわりのみ）。

## Goal

「正本1箇所 + 参照側を pin」という本 repo の確立済みの型を、まだ適用されていない6領域へ広げる。

## Value

integrity（RMSE 一致の前提=同一依存の機械的担保）/ failure detection（outputs 改名の沈黙劣化の検出）。

## Context

反証3（親調査 §2）により依存 pin の不足は**2箇所のみ**と判明済み。outputs 契約の pin 不在（C1）は第2回の新発見で、terraform_vars が潰したのと同じ構造の穴。

## Scope

1. 依存 pin: `SERVING_PIP_REQUIREMENTS`（databricks/job_main.py）と orchestrator Dockerfile を契約テストへ追加。`lightgbm==4.6.0` 系の範囲非対称を pyproject 由来へ統一。散在する検査（test_packaging_contract ↔ test_snowflake_adapter）の集約
2. serving 契約: ルート/ポートを `core/app` の公開定数化し、vertex/azureml の定数は import（platforms→core は合法方向）。Dockerfile の 8080 は契約テストで突き合わせ
3. Neon env 名（POOLED 3定義 + DIRECT 2定義）: 正本を `platforms/neon` 配下の stdlib-only モジュールへ + 一致テスト
4. **Terraform outputs 契約**: `OUTPUT_FIELD_MAP` ↔ 実 `infra/environments/*/outputs.tf` の pin テスト（tests から infra/ を読む）+ `_resolve()` の沈黙フォールバック廃止（必須 output の欠損は即エラー）
5. 名前の正本化: `mcml` prefix・リソース名（TF `local.name_prefix` ↔ config.yaml ↔ adapter 既定値）・env↔platform 対応（7箇所）の集約と pin
6. イメージ名/タグの正本化（ローカル名3ファイル5箇所・組み立て規則3実装・`latest` 3箇所）+ `load_outputs` 3実装の統合

## Non-scope

- config.yaml platform 節の未知キー検査（→ P6。設定解決の挙動変更なので分ける）
- 依存の版そのものの変更（pin の形式統一のみ）

## Done

6領域それぞれに「正本1箇所 + pin テスト」が成立し、`make test` 緑。意図的に値を1つずらすと対応する pin が赤になることを各領域1回実演。

## Evidence

Level 2: 各 pin の赤の実演（例: outputs.tf のキーを仮改名 → 新テストが赤）+ `make test` 緑。

## Stop / Ask Owner If

- 5 の名前正本化で「TF 側を正とする」以外の案（config.yaml を正とする等）に分岐したら方針確認
- outputs の沈黙フォールバック廃止で、意図的に output を省略している環境（deploy 無効時の null 等）の扱いが自明でなくなったら確認
