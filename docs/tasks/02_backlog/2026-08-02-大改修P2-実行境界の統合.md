# 大改修 P2: 実行境界の統合（platforms/runtime）

Weight Class: **Heavy**（Task Contract Full）/ 親調査: [大改修 調査と方針 第2版](../01_idea/2026-08-02-大改修-5インフラ制約起点の再設計-調査と方針.md) §5-P2
実施前に **SPEC.md**（§6 の5基盤制約表 + 触る番人の列挙を含む）を書く。**Owner Approval 必須・D1 の判断が先行条件。**

## Goal

学習実行の入口の4重実装（Tier A シム3枚の引数パース・Databricks `job_main` argparse・Snowflake `sproc_handler`、および MlRun 構築×4）を、`platforms/runtime/`（仮名）の共通 Python 実装1つ + 各基盤の薄い翻訳へ統合する。

## Value

integrity（記録スパインの一貫性）/ dev speed（引数契約の変更が1箇所で済む）。

## Scope

- `platforms/runtime/` 新設: 引数/JSON/VARIANT の正規化 → `core.ml` 呼び出し or 記録 → exit 翻訳
- Tier A シム3枚を「基盤固有の前処理 + `python -m platforms.runtime.*` 2コマンド」へ縮小
- `job_main.py` / `sproc_handler.py` を runtime 経由へ
- 配布3点の同時修正: Snowflake zip `included` に runtime 追加 / 学習 Dockerfile に `COPY src/platforms/runtime` / （wheel・orchestrator は自動）
- 既存番人の同一コミット更新: `test_core_boundaries` の `NON_PLATFORM_PACKAGES` に `runtime`
- 新番人: 「5入口が同一 runtime を呼ぶ」「MlRun 構築は repo に1つ」（`sinks.record_to_run` と tests/fakes は免除）
- D1 = O2 採用の場合: sproc に try/except を足し失敗 JSONL を証跡として stage へ PUT + 再送出、系統差として 05_snowflake.md へ追記

## Non-scope

- **Tier A シムの1プロセス化**（反証2により恒久非対象。OOM 時の記録堅牢性を守る）
- runtime から `platforms.shared` の import（zip に shared が無い。制約として SPEC に明記）
- SageMaker pre-flight（`/opt/ml/output/failure` の python 起動前書き込み）のシムからの移動
- 行所有規約の改訂（D1 = O1 を owner が選んだ場合は本 task を分割して再起票）

## Risk

- 記録スパインの構造変更。ユニット緑でも実クラウドでしか出ない欠陥の前例が6件ある領域（decision-log 8/2）
- 配布3点の同時修正漏れ → Snowflake / Tier A 学習が起動時に落ちる（実 zip・Dockerfile で確認済みの必須変更）

## Change Condition

D1 の owner 判断（O1/O2）確定 + P1 完了（相対 import 穴の封鎖を含む）+ SPEC.md 承認。

## Done Condition

`make test` 緑（新番人含む）+ 5入口すべてが runtime を経由することを番人が pin + 配布物検査（zip 内容・Dockerfile COPY）の契約テスト更新。この時点で `04_verifying/` へ mv し、**実クラウド確認は [P8 検証キャンペーン](2026-08-02-大改修P8-実クラウド検証キャンペーン.md)で実施**（単独でクラウドを起こさない・owner 採用の検証戦略）。

## Owner-only Decisions

- **D1**: Snowflake ジョブ内失敗の扱い — O2 記録して受け入れる（推奨）/ O1 行所有規約改訂（Tier A 波及・EL4 前提）
- runtime のパッケージ名（`platforms/runtime` 案）

## Capability Boundary

クラウド資格情報・実接続は使わない（実装・検証ともローカル）。Neon への実書き込みなし。

## Allowed Paths

`src/platforms/**` / `src/core/telemetry/`（参照のみ・移設は P3）/ `docker/training/**` / `docker/orchestrator/Dockerfile` / `tests/**` / `docs/02_architecture.md` / `docs/comparison/05_snowflake.md`（O2 の系統差追記のみ）/ 本 task と SPEC.md

## Forbidden Paths

`docs/comparison/` の実測値・既存記述の書き換え / `sql/**` / `infra/**` / `src/core/ml/**`（tree hash 不変）

## Rollback Trigger

- 計画外の番人赤（触る番人の列挙に無いテストが落ちた）
- RunSink 契約（record_run / next_attempt の2メソッド pin）を変えたくなった — それは設計が inside-out に戻っているサイン。停止して owner へ

## Evidence Required

Level 2（実装時）: 新旧の入口が同一入力で同一の MlRun を組むことの等価性テスト + 番人の赤の実演。Level 4（P8 キャンペーン時）: 5基盤で write_path / attempt / failure_class の意味論が実測不変。
