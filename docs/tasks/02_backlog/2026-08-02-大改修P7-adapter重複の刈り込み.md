# 大改修 P7: adapter 重複の刈り込み

Weight Class: Light / 親調査: [大改修 調査と方針 第2版](../01_idea/2026-08-02-大改修-5インフラ制約起点の再設計-調査と方針.md) §5-P7
**最後に実施**（P2〜P6 で構造が確定してから。早すぎる共通化はこの repo の既知の失敗形）。

## Goal

adapter 間の逐語一致コピペ7パターンのうち、「5基盤で**意味まで**同一」なものだけを shared / TrackedOperations へ移す。

## Value

dev speed。

## Context

候補（第1回調査 §6・実在確認済み）: `model_artifact_uri` ラッパ×5 / `_endpoint_exists` パターン×3 / 空 predictions ガード×5 / `_Entities` 遅延 import 窓口×2 / Databricks `result_state` 判定の内部複製 ほか。判定基準は `ports.py` の「port を切る基準」— 差を隠さない。

## Scope

- `plan-refactor` スキルの手順で7パターンを個別判定（共通化する / 意味が違うので残す、を1件ずつ記録）
- 共通化するものだけ実装。残すものは「なぜ残すか」を各 adapter のコメントか本 task に記録

## Non-scope

- 意味の差があるものの統一（例: predict_one のレスポンス解釈が基盤で違う部分）
- 新しい port・Protocol の追加

## Done

7パターン全件に判定が付き、共通化分は `make test` 緑で移動完了。共通化 0 件という結論も可（判定記録が成果物）。

## Evidence

Level 2: `make test` 緑 + 判定表（パターン / 判定 / 根拠）を本 task に記録。

## Stop / Ask Owner If

- 共通化の過程で adapter の挙動（記録される MlRun・例外方針）が1つでも変わる案になったら停止
